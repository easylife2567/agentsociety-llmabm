# Experiment 2：timestamp策展三臂主实验

> 2026-10-08设定复核：用户要求interest的全部100位Agent在W13收到官方帖，再由原U决定发言；chronological与random允许因推荐规则漏读，并希望对照局限于算法层面。17条历史池暂时接受并保留。事件时钟与算法比较范围的备选方案见文末，尚未采纳或实施；当前九配置保留为修订基线，本轮不启动LLM。

用户明确要求采用到达时机任务中的timestamp方案，并将其纳入主项目实验设计。主实验此后以本节为设计依据；experiment_1完整保存历史设计和结果。采用理由有两项：真实帖子按发布时间取得推荐资格，避免提前获知未来信息；用户对四格曲线的比较认为timestamp-interest最贴近现实的增长、衰退与后期玩梗形态。该观察足以支持当前方案选择，无须等待更多seed才作取舍；其跨seed稳定性和同口径误差由后续结果评估。

本实验承接已采用的timestamp主设计。`timestamp_v1`为本experiment_2的批次标识，本轮仅准备与离线验收、不启动LLM。旧`anchored_v1`、`weekly_lag1`、四格诊断及离线图各按原身份保留；experiment_1的官方`run`链接仍指向既有anchored_v1结果；experiment_2没有运行结果或run链接。

### 到达、推荐与回流

普通真实帖的共同资格条件为`published_at <= acted_at`；日志同时保存真实发布时间和推荐可用时间。Agent帖还必须满足本臂回流资格。缺少普通真实帖时间戳时应在冻结前报错，不按周一补时间。W11初始池只含窗口开始前已发布的历史帖子；原source_week保留作审计，资格与统计周由Asia/Shanghai时间推导。

官方讣告三臂均从`2026-03-24 20:00+08:00`取得资格。这是已使用的建模约定，原始官方帖没有观测发布时间；不增加全员死亡通知或事件效用加成。

| 推荐臂 | 选择规则 | Agent帖回流 |
|---|---|---|
| random-global（配置值random） | 截至行动时刻已发布且具资格的全部历史帖子，最多10条均匀无放回抽样；无生命周期、置顶、保底、兴趣或热度权重 | 发布所在周的下一上海周周一开始可见，当周不回流 |
| chronological | 截至行动时刻已发布且具资格的全部帖子，按精确发布时间倒序取最新10条；无生命周期、置顶、保底、兴趣或热度权重 | 同小时批次结束后统一入池，从后续行动批次可见；同批互不可见 |
| interest | 保留倾向分×兴趣匹配、生命力、曝光饱和和比例抽样；半衰期1.5周、退场线0.35、饱和尺度20、温度4，其他值以冻结配置为准 | 与random一致，次周回流 |

interest的官方置顶与W13最多5条议程保底，只在讣告取得资格后启用；每批仅从当时具资格的候选池选择，不用未来帖子补槽。保底可不足5条，不复制帖子。整数周龄继续按发布周计算，不能因小时步进而重复老化；R按实际个人累计曝光更新，不额外按小时衰减。

三臂共同采用真实信息时钟和配对行动表，但保留既有候选池、议程位及上述回流制度差异。研究比较的是完整策展制度效应；本次没有采纳把三臂回流全部改为次周的方案，也不称为同候选池、同回流下的纯排序效应。现有四格只验证interest/random的到达时机，没有新chronological结果。

每批先推进具资格的真实帖和本臂回流队列，冻结全部当批行动者的feed及曝光状态，再完成数值判定与生成，批末统一提交曝光和产出。相同输入下的feed不得依赖Agent遍历顺序、服务返回速度或入池自增ID；稳定来源键、并列排序和按seed/周/Agent/用途分流的随机数写入manifest。周末尾部真实帖照常记入发布周库存，不额外增加行动；最终排空窗口内到达队列并写11周汇总，不加W23。

### 保留发言的内容修复与记账

沿用用户已采纳的“只修错误细节，发言不减量”：先作有依据的局部修正；整段拒答、空输出或生成故障使用有限重写/重试，耗尽已冻结尝试额度后采用基于当次所见的保守短帖兜底。不虚构人物年龄、事件日期或经历，不把作者人设属性当作讨论对象的事实。相对日期依据来源时刻理解，不能仅凭发布时间机械换算转载中的“昨天”。

数值达到门槛且有可见依据的Agent保留发言意愿；生成问题通过修正或兜底形成可发布正文。首次和后续实际发送消息、完整服务返回、编辑、重写、技术重试及兜底来源分别留账。每次行动至多执行一次成功发布，只有环境确认成功并返回帖子ID才记成功；发布基础设施失败如实留账，不制造成功记录。空feed不构造气候、不生成无依据内容，记为无内容支持的行动机会；此时不是已有发言意愿被内容检查取消。

19条问题帖、agent79拒答、agent56/43相对日期实例（20条冻结必查集合）进入两类行动路径的验收；45条额外规则命中仍待人工确认，不把筛查数当真实缺陷率。现有18项离线功能检查、20样本×两入口和四格静态794条保留可作为继承证据；它们不保证新正文质量或新闭环产量。新生成改变interest特征和后续feed，因此234/214/177/169是归档固定供给数，不是新主实验产量目标。

### 指标、现实比较与解释

- 机制指标：各类型人口→发言→供给→曝光的漏斗；W19–W22玩梗作者供给及曝光份额、曝光相对供给的放大、各臂差值；分开报告外部帖和Agent帖。

- 测量对象：作者参与/供给曲线、词表信号和正文语义类别分开。作者类型继续用于pool_type和原回流，不用事后语义标签改推荐输入。

- 重复与边界：9个run各自报告完整矩阵及seed差异，不能把100人×11周当独立实验重复；既有单seed诊断只作选择依据，不改称已完成9-run新版本。

## 最终patch解释与离线结果

[最终patch](2026-10-08-01-timestamp.patch)只涉及三个既有文件：

- `curation_arrival_schedule.py`：支持chronological全历史候选和稳定时间排序；同批feed冻结后再入池、记录当周实际供给，避免周观测遗漏。random/interest仍次周回流。
- `curation_arrival_action.py`：从新profile接入共享额度与独立ledger；未配置此字段的历史诊断仍保持440次接口。内容修复和数值行为不变。
- `curation_dynamics_space.py`：仅在arrival模式允许chronological读取共同历史初始池；已有时序模式及滞后/官方例外限制保留。

官方配置prepare、validate、info、run、check通过。九配置分别通过schema和正式环境实例化，900个Agent工作区实际创建并核验共享预算。九个完整窗口环境演练各693批、1100条行动记录、11条周记录；未来曝光为0，三臂回流、同批隔离、稳定并列排序、恢复一致性和周度供给守恒通过。联合功能检查24项通过，包括20条必查历史样本在两行动入口、拒答有限重写/兜底、真实ID确认和共享额度耗尽；网络连接尝试0、LLM调用0。

这些是功能验收：全窗演练不生成模型正文，生成测试用固定服务返回，不能证明新九run产量、曲线或模型生成质量。完整结果分别保存于[功能记录](2026-10-08-02-functional-verification.json)和[配置/源码冻结记录](2026-10-08-03-configuration-verification.json)。

实现时的直接失败经验：构造器曾拒绝时序臂的共同初始池，已将许可限定于arrival模式；独立审查发现时序帖已入池但周观测遗漏，已修正并增加跨周真实发布守恒检查。生成提示对词表的使用是从实际可见正文筛选已见词，manifest据此准确登记。上述事项是工程问题，不作为拟合好坏的证据。

常态锚点限制继续披露：现有B使用W05–W12供给形状，但换算尺度为W13悼念峰的22/4714，并包含小数期望落floor的机制；不是独立事件前估计。用户要求保留当前行为参数，因此本实验不替换B、不重新标定。独立baseline-anchor数值探索已结束，候选未采纳；timestamp消除帖子提前到达，不意味着人口、词表或B全部只来自事件前信息。

## 分臂官方帖可见性与历史初始池复核

### 官方帖的到达、实际阅读与W13机会

用户的当前裁定是保留推荐制度造成的官方帖可见性差异，而非三臂共同必读。interest的W13覆盖目标为全部100位Agent，包含22位悼念Agent；阅读后按原U公式和门槛决定是否发言，chronological和random允许漏读。用户同时希望对照只改变算法，具体机制范围与时间方案尚未采纳。官方帖当前从`2026-03-24 20:00+08:00`才取得资格，该时刻是诊断建模约定，不是原帖观测；W13自然周起点为3月23日00:00。

所有九份配置均复用同一行动表，22位悼念Agent中的20、21、22、56、70在官方时刻前已经行动（分别为3月23日20:00、15:00、18:00，3月24日16:00，3月23日12:00）。每周只能行动一次，这5人的W13决策发生在官方帖取得资格之前。应将“行动早于发布”与“发布后未被推荐”分别记账；前者不能靠interest置顶解决，后者是random/chronological允许产生的制度结果。现有时间门控功能验收通过，不等于interest的W13全部22人覆盖已满足。

共同入池不等于共同阅读。已有timestamp四格归档的W13中，random只有1/22位悼念Agent在数值feed与实际前五条生成上下文看到官方帖，interest为17/22。random另外16位虽在入池后行动，仍没抽到这条帖；这不等于他们未从其他帖得知离世。只把官方注入时刻提前，不保证22/22覆盖。当前arrival快照的event_signal为空 ，也没有独立公共公告渠道。

采用的分臂规则如下，均不增加行动机会或效用加成：

| 推荐制度 | 官方帖的推荐方式 | 悼念Agent漏读的解释 |
|---|---|---|
| interest | 保留既有官方置顶；在W13的发布后行动中，官方帖进入数值feed和实际前五条生成上下文，发言仍由原U决定 | 发布后获得行动机会的人应读到；当前17人均满足。另5人因发布时间前已行动而未读，属于待明确的时钟问题 |
| chronological | 从当时合格池按时间倒序取最新10条，不置顶或保底 | 官方帖可能已被后续帖子挤出前十，漏读属于合法结果 |
| random | 从当时合格的全历史池均匀无放回抽最多10条，不置顶或保底 | 官方帖可能未被抽中，漏读属于合法结果 |

interest的确定性覆盖依据是保留的官方置顶制度，而非兴趣权重本身必然选中该帖。既有置顶适用于具备阅读机会的全部Agent，不在本轮缩为仅对悼念类型强推。random和chronological的W13悼念波峰较平、或峰值落在W13之后，均是允许检验的结果，不作为启动失败或必须修回W13的判据；具体走势仍需完整仿真输出。漏读官方帖也不等于没有从其他悼念帖获得事件信息。

剩余时间问题须单独裁定：若保留当前官方时刻及原行动表，interest能保证的是发布后有行动机会的17位悼念Agent，不能保证W13全部22位。按当前100人共同小时表，30人在周起点后的第44小时之前行动，70人在该时刻或之后；因此全员100/100目标还涉及其他类型的25人。现有行动表最早在周起点后第6小时行动。全员覆盖必须处理事件时钟或行动安排，不能仅修补5位悼念Agent。本轮未选择或实施具体时钟修订。

### 全员触达与算法对照的备选设计（未采纳）

本节是针对用户目标的设计建议，不替代已冻结配置，也不代表新增实验已经获准。依据为当前ArrivalSchedule的实际分支、Agent的小时门控与用户的全员覆盖约束；具体时间映射是待审查的工程设计，不是实测活动规律。比较时应明确被操纵因素并避免把多个机制的差异混作一个效果，这一通用原则可参考[NIST实验设计术语](https://itl.nist.gov/div898/handbook/pri/section7/pri7.htm)，它不证明任何现实平台必然让100人收到讣告。

**时间方案一：官方事件统一设为W13周初。** 三臂从`2026-03-23 00:00+08:00`起都可推荐官方帖，保留现有行动表；仅interest在W13置顶第一槽，其他两臂正常选10条。当前所有人的W13行动均晚于该时刻，因此在置顶规则正确执行的前提下，可以保证interest全员在唯一决策前收到。保障来自置顶，提前入池本身不保证选中。此方案必须作为周级事件冲击说明：官方正文明确写“今晚（3月24日）”及当天下午离世，周初实际为3月23日；原文不能在严格日历仿真中提前当成已经发生的事实。若选择粗粒度事件周设定，应保留原文及真实日期证据，显式区分原始事实与仿真事件时钟，并解决生成提示的日期含义，不能伪造观测published_at或声称全部信息仍严格遵守现实日历。

**时间方案二：保留目前事件日历时刻，统一设置W13事件后决策窗口（优先建议）。** 官方帖仍于3月24日20:00取得资格；将原先在这之前的30个行动机会按事先登记、与类型无关的规则安排到发布后且不超出W13，其余70人的安排可保留。三臂使用同一调整表，每人仍只有一次机会，其他周保留原表，官方取得资格后再按各臂选帖。不要把30人全部集中到发布瞬间制造共同首批洪峰。此设计保证所有人具有事件后阅读机会，interest由置顶保证100/100，其他两臂仍可漏读；代价是W13的行动安排不再完全复用事件前周分布，须表述为事件周的受控参与设定。20:00仍是预登记近似时刻，并未变成原帖实测发布时间。实现时环境和Agent都要读取同一周专属行动表，不能只改steps，因为当前两处都校验固定小时。

仅统一事件时钟还不足以得到算法对照。当前`candidates()`只为interest排除退场历史帖，`step()`让chronological帖批末可见、其余两臂次周可见，interest另有官方置顶及5条悼念议程保底；这些均会影响U输入与供给反馈，不能因配置只差algorithm字段就称纯排序效应。备选规范如下：

| 项目 | 统一设置或算法变量 |
|---|---|
| 人口、行为、时钟 | 相同100人、原B/R/D/U公式与门槛、相同配对行动表、相同官方可用时刻和普通真实帖发布时间 |
| 初始与外部输入 | 同seed保留同17条历史及250条窗口样本，不额外重复官方帖或补造悼念库存 |
| 候选资格 | 使用相同规则。例如三臂均采用已发布且已可用的全历史池；生命周期可以作为interest的评分特征，但不再只为它改变候选资格 |
| Agent帖回流 | 三臂选定同一规则。为尽量保持当前interest/random反馈节奏，可统一次周回流，修改chronological；若强调小时互动，则统一批末回流，修改另外两臂。两者不能并存为“只差排序”的对照，本轮均未采纳 |
| feed与生成 | 每次最多10条，官方仅占其中一槽，不增加第11槽；三臂共享至多前5条生成上下文与120字摘录合同、内容修复和发布记账 |
| 悼念议程保底 | 为缩小额外差异，建议三臂均关闭独立5条议程保底；interest保留满足用户目标的单条官方优先规则。该建议尚未采纳 |
| 唯一变化 | feed选择函数：interest为W13官方优先＋其余槽兴趣选取，chronological为最新10条，random为均匀无放回最多10条 |

这可以解释为在共同信息与反馈条件下比较三种推荐算法，其中interest包含明确的事件优先规则。若研究主张限定为“仅兴趣匹配权重的作用”，interest独有的官方优先和生命力/饱和权重仍不能混入该主张；有限槽位的概率兴趣抽样也不天然保证100/100。应选择“含官方优先的兴趣推荐算法”作为研究对象，或另行拆分这些机制，不能通过改名称掩盖其差异。本节优先建议前者以满足用户当前前提，不重提三臂共同必读。

相同回流规则不要求三臂后续生成内容完全相同。各臂因为不同曝光而产生的供给差异，是推荐算法在闭环中的后续效果。验收则应确认从相同状态输入开始，候选资格及回流规则相同，只有选帖函数变化；实际闭环内容允许分化。

采纳后的离线验收至少包括：interest在W13的100/100数值feed均含官方帖，全部行动的可读正文摘录含官方帖；对实际发言者另核验发送给模型的上下文，未发言者不因没有生成请求而计为漏读。100人各一次机会且在官方取得资格后；chronological与random严格按各自规则选帖，不因未覆盖官方而判失败；三臂候选资格与回流一致、同批隔离、普通未来帖曝光0。发言仍按U，不要求100人或22位悼念Agent全部发布。实现将通过正式模块与配置生成器的最终patch、独立审查及重新冻结落地；本轮只记录建议，不修改代码、配置、manifest或机器阶段，不运行LLM。

### 17条历史帖的来源与影响

用户暂时接受当前17条历史帖，并以上传的“各内容类型发言量变化（堆叠面积·绝对数量，宽口径48706条）”作为现实对照。图中事件前营销占主导、W13悼念集中增长，与当前历史池以营销为主、无悼念的方向一致。图的全量统计与小样本不是同一数量尺度，图中“存疑”也不直接等同输入的noise标签；本轮据此保留现有历史初始条件，不将视觉分布合理性写成17条数量或全部反馈影响已得到定量验证。

正式环境会把这些帖送入推荐、气候与累计曝光；会改变D/R、其他类型供给及未来回流。random持续保留历史，interest在W13时的历史生命力约0.397，仍高于0.35退场线；chronological较早被新帖挤出前十，三臂受影响不同。
