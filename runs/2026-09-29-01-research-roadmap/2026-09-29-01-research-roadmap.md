# 课题推进方案与实验脉络

## 任务说明

本任务为“算法策展如何改变公众人物身后数字表征”建立可交接的工作入口，帮助用户决定下一步是否实施真实帖子到达时机实验。工作区保留 AgentSociety2 官方文件夹组织；根级 runs 仅作为新增的研究思路管理入口，data 是用户新增的实验预处理数据目录。范围是工作规范、阅读导航、证据分类和后续决策顺序；不修改仿真代码、正式配置、原始结果或研究流水线，不启动实验。

本文维护同一主题的事实、方案、依据和验收要求；实时进度、待决策事项和审查结论只写在本目录 README。后续复核更新本文，不按对话轮次另建版本文件。

下表登记历史事实及证据用途，不是新实验的执行清单。完整性数字依据既有归档清单；本任务未重新读取全部 replay 验算。

| 实验或材料 | 研究用途与做法 | 执行事实 | 证据地位与限制 |

## 工作方式

### 任务与目录

根级 `runs/` 按研究问题或交付目标组织思路、方案与决策，命名 `YYYY-MM-DD-NN-NAME/`。同一问题的复测、参数扫描和结论修正留在同一任务，不能把每个 seed 或对话轮次建成新任务。任务目录 README 管目标、一级资产、实时进度、证据入口、下一步和交接。

现有 `hypothesis_4/experiment_1/runs/` 是引擎实验批次目录，`data/` 是用户新增的实验预处理数据目录，其中 `data/runs/` 保存相关处理产物；均保留原职责。任务通过路径和 manifest 引用它们，不复制原始结果。任务探索脚本、方案、patch、解释性实验报告放任务目录；正式代码、实验配置、引擎运行结果及配套测试继续放官方对应位置，任务文档只引用，不构建另一套实验目录。临时日志放任务 `tmp/` 并忽略；唯一的结果证据不能只放 tmp。任务收敛且用户授权后才将成熟任务资产迁出为长期资产。

### 单一状态职责

- 根 README：项目介绍、一级目录与根文件索引，指向工作入口。
- `runs/README.md`：任务目录导航；只标识活动入口，不复制任务详细进度。
- 任务 README：该任务的唯一人工实时状态与 handoff。
- `.agentsociety/progress.json`：CLI 管理的机器流水线阶段；不手写第二份流水线状态。
- 方案、实验报告：方法、完整结果矩阵、失败经验、证据及边界；不维护独立进度表。
- 冻结 manifest 与原始日志：可复现证据，保留原貌。发现过期活动来源清单，在使用前修正；不能篡改冻结历史去适配新结论。

### 从讨论到实验的顺序

| 环节 | 要交付的内容 | 可以进入下一步的条件 |
|---|---|---|
| 事实核对 | 现有代码行为、配置版本、研究问题和直接证据 | 用户能分清事实、推断和建议；不存在会误选数据源的冲突 |
| 方案讨论 | 同一份规划报告中的范围、对照、预算、成功/失败解释 | 非小任务完成一次关键方案审查；尚未裁定的研究选择清楚列出 |
| 方案冻结 | 明确采纳的版本、固定项、变量、指标、运行矩阵及预算 | 用户对关键研究取舍有明确裁定；已有授权不反复确认 |
| 实现和验证 | 新文件、既有代码的最终 patch、必要功能检查 | patch 在声明的基线可应用，功能验证通过，独立子 agent 审查最终 patch |
| 诊断运行 | 已授权范围内最小且能回答问题的完整实验 | 不因拟合好坏临时改判据；异常有原因与证据 |
| 结果判断 | 同主题实验报告中的完整矩阵、限制与结论 | 决定是否扩种子、扩算法、修订机制或收窄主张；不默认追加实验 |
| 收敛交付 | 解释 patch、结果证据、最终 README | 当前任务提交完成；任务资产迁出须已有用户授权 |

已授权且必要的步骤自主推进；“建议”“讨论”“方案审查通过”不自动等于新增昂贵实验、变更主方案或迁出资产的授权。不能因为用户询问某个局部问题，就放弃当前总目标或自动扩大实验矩阵。

### 本次文档落地方法

修改 `CLAUDE.md` 的规则正文并保留 `AGENTS.md` 链接；根 README 改为一级导航；添加任务索引、当前任务 README 与本方案；为根级任务 tmp 增加精确 gitignore 规则。文档、gitignore 与新文件不属于“修改已有代码”，本次无需制造 `.patch` 或 patch 解释报告。没有实验结果时也不生成空实验报告。

### 后续代码的 patch 方法

每个 patch 声明相对仓库根的目标路径和基线 commit。先保存最终 `.patch` 并在干净的基线副本检查、应用，再检查目标工作区无冲突并应用；多轮开发后交付基线到最终状态的整合 patch。中间开发记录由 Git 保存，不在最终 patch 叠放修补 patch。新增文件直接创建，删除与文档修改按各自操作完成。若目标已有他人的未提交修改，不能覆盖或混进本任务 patch。

独立子 agent 只审查最终 patch 与相应方案、功能证据，不代替功能测试，也不改研究流水线。方案审查和代码审查各保留关键一次；只有实质变更或未解决的问题才复审。普通小改动适用用户规定的简化例外。

## 候选时间实验如何进入此流程

后续若用户决定继续，在独立语义任务目录内形成一份时间实验规划报告，本任务只保留索引。当前候选范围为100人、11周、每人每周一次机会、效用参数冻结、Agent 帖次周回流；真实帖到达方式为主要对照。首批候选矩阵为2种到达方式×2个算法×seed 0，共4个完整 run、4,400次行动机会。

这些是建议值，不是运行授权。方案冻结前要明确：要保留的科学主张、行动表、初始池、讣告与背景知识、时区、少量/空 feed 规则、指标与解释边界，以及运行时间/费用预算。共同接口修改的影响与帖子到达时机的影响要分开。已有材料可引用，不再另起大量平行说明文档。

后续扩展只按结果和研究需要决定：按时到达两臂补齐3 seeds 后累计8个新 run；两种到达方式均补齐3 seeds 为12个；再加统一调度的 chronological 三个 seeds 为15个。三个档位是替代性的投入选择，不是默认执行队列。

## 验收标准

1. 保留 AgentSociety2 官方目录结构，明确根级 runs 与 data 为用户扩展；规则同时适用于现有 AGENTS.md/CLAUDE.md 入口，不丢失 Python、CLI、单写者和研究阶段要求。
2. 用户从根 README 经 runs README 能找到本任务目标、资产、进度与待决策事项；无独立 tracker。
3. 已有实验、敏感性、数值代理、撤回设计与未运行建议清楚区分；关键证据路径存在。
4. 根级任务 tmp 被 Git 忽略，而 README、报告和未来 patch 可以正常跟踪。
5. 本次不改仿真代码、正式配置、原始结果、分析来源清单或流水线状态，不启动实验。
6. 最终 Git 提交只包含本任务文件；保留工作区既有无关 Excel 修改。提交使用中文 Conventional Commits，正文解释原因、影响和注意事项。
