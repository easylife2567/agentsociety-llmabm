## 当前判断

扩大到500人是合理的优先方案：最小的教育型群体从15增至75，能减轻少数个体对群体参与率的影响，同时避免直接承担1000人的全部开销。但不能提前保证曲线更平滑、结论不变或可信度提高到某个数值；这些要由实际跨重复结果证明。1000人可作为预算允许且仍需检查规模稳定性时的后续选项，不自动加入实验矩阵。

“随机性”需分开看：

- **人口与群体波动**：100人中教育型仅15人，一人发言与否使该类每周参与率变化约6.67个百分点；500人时为1.33个百分点，1000人时为0.67个百分点。这是比例最小刻度，不能冒充实测误差或置信区间。
- **个人所见的抽样波动**：每人只看10条帖子；增加总人口不会让每个人所见自动更全面。若把10槽一并扩大，就改变了个人信息量及注意力机制，需要单独论证。
- **整轮轨迹的随机性**：推荐抽样、人口参数和模型正文经回流传播，Agent之间有关联。500或1000人不能替代多个独立seed；一轮1000人仍只是一轮社会轨迹。
- **模型设定的限制**：扩大规模不自动解决B的标定、固定类型、历史输入及制度差异的解释边界，也不等于覆盖更多真实用户的独立资料。

建议保留三种制度×至少现有3个seed作为规划起点，先确定一个人口规模；若重点是估计跨轮不确定性，再比较“增加人数”和“增加seed”如何分配预算。3个seed适合查看方向和范围，不能仅因人数更多就按全部Agent独立抽样报告显著性。暂不预定更多seed，也不同时默认执行500和1000两套。

## 扩容前需要决定的机制问题

### 1. 真实信息输入与Agent生成供给的相对规模

若真实输入仍固定250+17条，而Agent数量增至5／10倍，新增表达可能使内生供给占比上升，真实输入及官方单帖的相对影响变化。这是机制推断，增长幅度依实际发言与回流，不预言恰好5／10倍。对chronological而言，更多新帖还可能更快挤走较早真实帖。

有两种可解释的选择：固定外部真实信息场，让更多人参与其中；或扩大真实样本，使外部输入与人口保持接近既有比例。前者回答“同一外部信息下扩大参与人口”，后者更接近维持信息供需密度的规模比较。两者都不是自动正确，必须先写明本轮假设。

若以现有数量等比例估算，500人对应1250条窗口帖+85条历史帖，1000人对应2500+170条；这些只是数量参照，未确认逐周、逐类是否有足够合法且不重复的真实来源。官方事件仍应是一条独立来源，不能为凑比例复制成5／10条；普通帖按来源、时间、类别重新冻结。不能把重复文本换ID当成更多独立真实信息。改变样本也会引入新的输入差异，应记录与旧版的关系。

**讨论建议**：以减少小人口波动为目的，优先把“个人信息量、外部输入与生成供给的相对规模”列为扩容契约，即明确哪些量保持不变、哪些按什么理由缩放。先明确这一点，再选固定输入或扩大输入；不在看到新曲线后反向决定。

### 2. 帖子累计曝光与个人累计接触必须分开

源码`curation_mechanisms.exposure_saturation`使用`0.5 ** (帖子累计曝光 / 20)`降低interest推荐权重。同一帖被更多人读到，后续权重下降；这不是超过20次后直接退场，候选退场仍按时间生命判断。若人口增多而输入不变，热门帖可能更快累积曝光，产生额外规模效应。

20是否应缩放，取决于它表示“固定阅读次数的疲劳”还是“触达一定人口比例后的饱和”。如明确采用人口比例解释，100／200可以作为500／1000人的候选尺度，但不能自动采用；若帖子总量也近似同比增长，平均每帖曝光可能保持接近，此时再放大该尺度可能过度补偿。应联合检查每帖曝光、候选数和人均阅读，不能只见N增大就所有参数同比放大。

个人注意力R使用`exp(-λ·个人累计同类接触/15)`。每人仍每周最多10槽时，15的个人单位没有因总人口变化而自动改变；不应机械乘5／10。个人门槛、B、D的群体比例基线也不自动放大。保持比例时`_POP_SHARE`数值仍适用；若将来改变人口比例，硬编码基线须同步审查。

B目前显式写入个人profile，其历史标定含22/4714及整数floor（向下取整）映射。暂以冻结的个人效用分布为参照；不能直接把B乘5／10，也不能重新跑一次旧100人标定器就声称已适配大人口。若决定重标定，应视为新的模型版本并披露，而非单纯扩容。

### 3. 新人口不能只是100份完全同步的复制

500和1000均可精确保留五类比例，不涉及类型人数的舍入误差。仍要明确个人门槛、人设及小时表的生成规则：完全复制原100份5／10次会复制其有限异质性；若连时间也复制，同类群体会成批同步，并不能等价于新增独立用户。重新分层抽样可增加个体差异，但必须保留既有分布依据，避免同时更换人口机制。

可讨论按类型使用同一参数分布、为新增Agent分配唯一ID与独立随机流，在三制度间冻结同一人口和行动表。不同规模采用嵌套人口（小人口是大人口的子集）有助于比较，但不是本轮必须新加的复杂功能；复制或重抽都应透明说明。不得把重采样模型人口称为新增了真实受访者。

### 4. W13规则与小时批调度要按规则扩展

当前5位早于讣告行动的悼念Agent被共同顺延，保证22人具有事件后决策机会。大人口不能只沿用这5个ID；若保留这一建模条件，就需要对新人口中全部符合条件的悼念Agent按事先规则处理，并在三制度共用，继续允许官方漏读。新安排是条件化参与假设，不能说成现实活动事实。

不能照抄“从63小时网格无放回选5个不同时刻”的旧实现：人数增大后，待顺延人数可能超过可用小时数，且多Agent同小时行动本来就是合法的。应预先决定是否允许同小时、多人的小时分布如何保持、是否保留旧网格。

新小时表可能改变调度批数量；693步来自当前63小时×11周的构造，不是所有人口都固定693。无论如何分批，每人每周恰好一次、同小时互不可见、跨小时回流、三制度配对、无未来内容等契约须保持。实现时需核对引擎将同一小时拆成执行小批后，是否仍保持社会层面的同小时隔离。

### 5. 费用、机器资源与旧入口限制

现有九次主批在10核／16GB机器串行执行，批次记录总耗时约8.09小时。按5／10倍粗乘分别约40／81小时，只是工作量参照，不是运行时间预测：原耗时含固定启动、调度和保存开销，新人口可能提高并发利用，也可能增加推荐评分、保存状态及接口等待。当前没有500／1000人的实测内存或吞吐数据，不能据此保证本机可承载。

interest为每个活跃Agent遍历、评分和排序候选帖；若人口和候选帖都随规模增长，这部分工作可能接近按人口平方增长，不能只按LLM调用线性估时。还需观察Ray对象存储、checkpoint（保存的恢复状态）体积、replay磁盘增量，以及服务限流。人口总量、引擎执行batch-size、模型接口并发是不同控制量，不能把它们统一改成500／1000。

旧生成器断言100人、固定5个W13 ID及1100行动，旧监督器硬编码1100验收并固定旧输出/账本路径，不能直接启动新矩阵。官方包装器status/stop未按run_id分离的问题也要避开。后续须在隔离workspace准备本run的独立配置、manifest、日志和账本，不改写或续用旧批文件。

本轮尚未统计实际token分布、读取当前报价或进行接口探测，因此不提供金额估计；需要预算时先用旧账本的实际token作为参考，再核实届时服务价格和模型版本。旧主批或消融的额度、48小时上限不自动覆盖新批。保留模型请求标识并记录API/后台差异；若与旧模型不一致，新旧差异还可能含模型变化。

## 如何判断扩容是否达到目的

正式运行前预设主要比较：三制度在W13悼念峰、W19–W22玩梗轨迹、各类参与率、真实与生成帖曝光份额上的方向、幅度及跨seed范围。首先检验原机制结论能否维持，而非仅检查曲线是否更平滑或是否更接近现实曲线。不凭结果挑选seed或规模，不把未预设阈值写成事先标准。

规模不同先比较比例、人均值和群体参与率，再补绝对帖量；不能把500人的原始总帖数直接和100人作强弱比较。分别报告固定作者类型、环境阅读标签及正文分类口径。新增人数不会自动解决正文测量误差。

建议的后续顺序：

1. 讨论并确定500或1000、输入缩放解释、人口生成与W13规则、固定项、主要指标，以及可接受时间/费用；此时再进入experiment-config等相应技能。
2. 获得实现指令后，在本run隔离workspace准备并离线核对人口/调度/输入/恢复/预算，保存最终patch及新增文件。离线检查不调用LLM，也不代替完整闭环结果。
3. 如需短程LLM可行性试跑，先明确其调用预算、用途及是否纳入正式分析；不把“讨论扩容”视为试跑授权。随后按新矩阵授权启动，保全失败记录，不自动扩大或重跑。
4. 在选定规模完成跨seed比较后，判断是否确有必要增加到1000或增加seed。若采用新的主结果，再由用户授权选择性正式落地；旧100人主批和消融保留其原始证据身份。
