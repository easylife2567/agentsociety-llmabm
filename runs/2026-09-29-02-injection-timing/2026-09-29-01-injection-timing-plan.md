# 真实帖子到达时机对策展制度差异的影响：实验方案

## 研究问题与范围

在共同的周内行动安排、人物设定、初始库存和表达规则下，普通真实帖子“整周提前进入候选池”与“到真实发布时间后才进入候选池”，是否改变 interest 相对 random 的曝光放大与表达差异？

本方案检验一个时间设定是否影响核心解释。保留100个固定类型 Agent、W12–W22、每人每周一次行动机会和锚定式表达效用，不重新标定参数。首批为2种到达方式×2个推荐制度×seed 0，共4个完整 run。先保留 Agent 帖次周回流，不同时增加同周传播速度。

这是一份供用户审核的设计，不代表已实施或获准运行。实时状态只在本目录 README。工作区保留官方结构；本目录管理研究思路，代码、配置及结果仍在对应正式目录。

## 主张与需要的证据

| 要检验的主张 | 最少需要的证据 | 首批能回答的程度 |
|---|---|---|
| 排除普通帖周内提前可见后，interest 与 random 的机制差异仍值得进一步验证 | 合规时间日志；按行动机会调整的曝光指标；作者群体参与及正文语义结果；四格对照 | 首批识别方向、幅度和失败机制；单 seed 不能证明稳健或统计显著 |
| 旧结果与时间有效方案的差异不能全部归因于注入时间 | 新实现两种到达方式的对照，以及旧 anchored_v1 与新提前载入条件的桥接比较 | 后者包含多项共同调整及 LLM 运行差异，只诊断整体差异，不识别各共同调整的独立效应 |

本实验不检验“真实后段走势完全内生生成”，不构成事前预测：仍持续输入真实后期帖子，人口与词表也含回顾性设定。算法对比仍是完整策展制度对比，不能解释成纯兴趣排序效应。

## 实验矩阵与固定项

建议 batch_id：`arrival_timing_diagnostic`。这是正式可追溯名称，四个 run_id 分别为：

| run_id | 推荐制度 | 普通真实帖可推荐时刻 |
|---|---|---|
| `arrival_timing_diagnostic_preload_interest_s0` | interest | 发布时间所在上海周的周一00:00 |
| `arrival_timing_diagnostic_timestamp_interest_s0` | interest | 实际 published_at |
| `arrival_timing_diagnostic_preload_random_s0` | random | 发布时间所在上海周的周一00:00 |
| `arrival_timing_diagnostic_timestamp_random_s0` | random | 实际 published_at |

preload 是有意保留提前可见的诊断对照，不是符合真实时序的模型。其人物可以从提前载入的真实帖获得尚未发生的事实；这属于被测处理，不能另加过滤暗中消除。timestamp 条件必须保证所有实际曝光及生成上下文不含尚未发布的帖子。

四格固定：

- 人口：营销23、悼念22、其他21、玩梗19、教育15；使用同一批固定个体与数值参数。
- 效用：`U = B + R × (D − B)`、原门槛、alpha_D 和各类型 λ；R 按实际历史同类曝光更新，初值累计量为0，不按小时额外衰减。
- 主输入：同249条普通真实帖、1条官方讣告；外加同17条W11初始池。总记录267条，初始池与窗口内新增分列，不重抽、不复制。
- 行动安排：复用已冻结的每人周内小时，11周重复；四格同一个表。首周首次行动为周一06:00，不在周一00:00额外发言。固定先后顺序及“发帖时间代理浏览时间”的限制写入结果。
- 每人每周一次机会，最多10条数值感知 feed；LLM 保留前5条、每条120字的文本预算，所有被实际传入文本记录下来。
- Agent 生成帖下一上海周周一才具备推荐资格；W22帖子照常统计，不延长W23、不在本周传播。
- 模型、服务、温度等生成设置跨四格一致并记录。相同seed不能保证远端LLM完全可重复，不能把一次成对差异当作确定性效应。

参数优先读取 anchored_v1 对应冻结配置。已核对：interest 帖子半衰期1.5周，退场线0.35，曝光饱和尺度20，比例抽样温度4；random 保持全历史均匀抽样。random配置中的某些参数虽存在，执行分支不使用，不能据配置键存在就声称两臂机制相同。

## 时间轴、事件与更新顺序

### 时间定义

全部比较与周界使用 Asia/Shanghai。保留原始 `published_at` 和原 `source_week` 作审计，新增由时间戳推得的本地周；不得把 UTC 周字符串直接当上海周。

窗口为 `[2026-03-16 00:00+08, 2026-06-01 00:00+08)`。s0普通帖按上海周重新统计为：17、34、30、24、22、19、17、17、21、22、26；W13加官方帖后为35。共249普通帖＋1官方帖，主样本没有越出窗口。与旧周标签不一致的6条不改正文或删除，只按统一时钟归桶。W11样本全部保留，其构成为营销14、教育1、噪音2；初始池偏向营销是已知限制，不以“平衡”为由临时重抽。

### 官方讣告与议程槽位

官方帖两种到达条件都在 `2026-03-24 20:00+08` 可用。时间沿用现有代码的明确建模约定，原帖没有观测时间，不能把20:00写成真实观测值。不提供额外全员死亡通知或事件效用加成。

interest：官方帖发布后才允许置顶；W13议程保底同样从该时刻启用，候选仅来自当时已具资格的非噪音、非置顶活帖，按既有哀悼倾向分取最多5条，不保证一定是5条，也不保证文本标签全是悼念。不复制帖子、不从未来补槽。random保持无置顶、无保底。两到达条件的启用时间和选择规则相同。

这意味着本批识别的是**普通真实帖到达效应**；不会单独识别官方讣告从周初改到20:00的效应。旧实验桥接比较包含这一共同调整。

### 一次小时批次

1. 若跨周，先收尾上一周统计，释放上周Agent帖，按周龄计算帖子生命；完成历史与真实帖的可用队列推进。
2. 将截止本批行动时刻具备资格的真实帖并入池；`published_at == acted_at` 允许。缺时间普通帖不得静默按周一回填。
3. 冻结本批候选池、帖龄、帖子累计曝光、个人历史曝光和已见集合。所有外部帖预先以来源命名空间×source_pid定义稳定键（包含初始池与官方帖）；Agent帖以作者×周定义稳定键。候选规范排序、并列破局、随机打分和抽样都使用这些不依赖入池或生成完成顺序的键，运行期自增post_id仅用于存储关联。随机数按seed、周、Agent与用途分流，逐帖噪声再包含稳定帖子键；批内换遍历顺序不能改变相同输入下的feed，不共用会被候选数变化推进的全局可变游标。
4. 装配本批全部人的 feed，记录候选构成、实际曝光及前5条文本；计算D、R、U与门槛。
5. 达到门槛且有可见文本时生成，发布成功才记作实际产出。新帖使用稳定的作者×周标识；排序平局不由LLM返回速度决定。
6. 全批结束统一提交曝光，更新个人累计量；生成帖等待次周。行为与统计分别写入行动快照和周汇总。

最后一个行动批次之后到周末的真实帖也要进入库存并按发布周计数，但未获当周曝光不是失败。最终W22周末排空到达队列并写周汇总，不产生额外Agent行动。693指行动批次预期值，周界处理不得暗中增加行动机会。

### 老化、空池与提示词

帖子年龄继续按本地产生周计算整数周龄，生命为 `2^(-age/1.5)`；不在每小时循环重复老化，不切换连续时间半衰期。Agent帖次周首次可见时为1周龄；W11初始帖W12亦为1周龄。random忽略生命门槛，interest沿用活帖资格。

非空且不足10条时使用实际条数计算类型份额，不补平滑先验；记录低支持度。空feed记为“无内容支持的行动机会”，不生成话题文本、不伪造曝光，不将其当作低效用沉默；U在该情形记为不适用，不用0条分母制造气候判断。

四格共同清理固定人设中直接叙述此人已离世的语句，保留职业、语气与群体倾向；悼念生成指引改为“仅在所见内容支持离世事实时回应悼念，否则回应实际所见内容”。生成提示不注入整周stock/flow，不强制使用从全窗提取的具体事件梗词库；测量/推荐打分词表保持冻结，区别于生成词库。不新增长期记忆模块，正文依据当前可见文本生成。

记录生成prompt中的帖子ID、截断后文本及成功正文，以便人工核查其依据；不增加强制复杂知识图谱或每帖额外LLM评判。对W13事件前的全部生成文本做人工时间依据检查，再对每run最多20条正文按固定seed分层抽查（前期/后期各最多10条，少于额度全查）。任何无可见依据的事件事实列为知识污染；若涉及核心结论，结果不得称为“已排除知识提前输入”。输入过滤并不保证清除LLM内在先验。

## 指标、统计口径与结论判据

### 时间和完整性是硬门槛

- timestamp两run未来真实帖曝光为0；所有run在讣告时刻前官方帖曝光为0、当周新Agent帖曝光为0。preload普通未来帖曝光必须单列，不要求为0。
- 每run100×11=1100个行动记录、11个周环境记录；每人每周一次且仅一次机会。按共享表核对693行动批次，不能只看进程completed。
- 267条外部记录唯一入库，区分17条初始存量与250条窗口新增；曝光次数、发布成功数和周统计一致。
- 发布拒绝/生成失败与真实不发言分开。存在未解决的缺行、重复、未来曝光或失败造成缺失时，不进入完整四格主比较。

### 决定性的曝光指标

对每次行动 j，在该制度完成时间与生命周期资格判断、尚未实施置顶/保底/个性化之前的候选池，记录总量 N_j、玩梗量 M_j，以及实际feed长度 n_j。定义均匀抽样参考期望 `E_j = n_j × M_j/N_j`。N_j=0时记 E_j=0 并单列空池机会。

窗口内实际玩梗曝光总数为 O，总期望为 E=ΣE_j。主要指标为超额曝光份额 `A = (O-E)/Σn_j`，同时报告 O、E 与有效槽位数。曝光放大倍数 O/E 仅在E>0时报告，E=0记不适用。既报告所有内容，也将外部真实帖与Agent帖来源分开。

这个参考基准条件于各臂自己的可推荐池，因此衡量该池上的分配偏离；interest与random的差异不能称为“固定相同池后的纯排序因果效应”。必须同时报告候选池类型组成、总曝光份额及生命周期排除量；置顶/保底槽位的贡献单列，防止将其归为兴趣匹配。正文语义与作者固定类型分开：内部type用于机制轨迹，assigned_type仅作冻结词表测量的语义代理，不冒充独立人工真值。

主要决策窗口固定为W19–W22，W12–W22作全窗补充，W13另做事件响应解释。不看完结果后挑窗口。

### 表达指标与对照差

主要表达指标：W19–W22中玩梗型Agent的成功发帖数、总发帖数与份额；每周活跃玩梗型人数；冻结词表独立判定的语义玩梗数/份额作为测量补充。需要同时读绝对量与分母，不能只凭份额上升声称玩梗生产增加。

对每个指标Y分别报告：

- `Δpreload = Y(preload,interest) − Y(preload,random)`。
- `Δtimestamp = Y(timestamp,interest) − Y(timestamp,random)`。
- `时间对制度差异的影响 = Δtimestamp − Δpreload`。
- 每个算法自身的 `Y(timestamp) − Y(preload)`。

四个run保持闭环，各自Agent供给自然演化，不强行让后续候选池文本相同。不能把1100个行动或11周当作独立实验重复；首批不计算跨seed显著性。所有差值照实列出，没有既定领域最小有意义效应量时，不事后发明“变化不到10%就稳健”的阈值。

### 结果如何改变决策

| 观测 | 允许的解释 | 下一步 |
|---|---|---|
| 合规时间下，曝光超额及参与差异方向仍支持原机制 | 在本seed与冻结情景下仍有支持信号 | 用户决定是否扩seed验证，不写“稳健性已证实” |
| 主要制度差消失、反转，或曝光与产出链条不一致 | 原解释存在时间敏感性或机制链条不足的诊断信号 | 先查曝光、来源与知识入口，不重新拟合来恢复曲线 |
| 大量行动缺少信息、库存衰退或初始池主导 | 缩小后的供给与时间分辨率可能不匹配 | 明确边界，另行决定供给支持度敏感性，不直接判机制失败 |
| 新preload与旧结果不同，而新preload/timestamp接近 | 共同接口调整或LLM运行差异可能更关键 | 不归因于注入时机，按证据决定是否进一步拆解 |
| 任一硬门槛失败 | 实现/数据有效性未通过 | 修复后重审受影响结果，不将故障解释成社会机制 |

“是否值得扩展”与“结论是否成立”分开：首批的作用是决定下一笔研究投入，不是完成正式因果验证。

## 旧实验桥接与评估数据

复用旧 anchored_v1 interest_s0/random_s0 结果作为历史参照，不重跑旧批。比较相同作者口径的周总量、玩梗参与和W13悼念响应；新指标若旧日志缺候选快照，则不伪造旧基准值。旧运行没有准确行动时间，无法对其Agent周标签做精确时区重分桶，应注明这一限制。

当前 `presentation/hypothesis_4/data/analysis_sources.json` 仍指向过期主批次，本实验使用独立manifest明确列出四个新run及两个历史参照，不能复用该活动来源清单。旧HYPOTHESIS中event_v2文字也不能作为运行依据。新方案不自动修订主假设或覆盖历史文件。

真实曲线拟合只作补充描述。若需同轴比较，另生成上海周界的真实基准，保留旧UTC基准；本轮不因新基准重标定B、alpha_D或λ。因此不能声称全部设定均已转换为严格事件前估计，尤其不能把失败解读成某一机制已被彻底反证。

规模固定建议：4run×100人×11周=4,400个行动机会；4×693=2,772个行动批次；每次最多10槽，理论曝光上限44,000。成功内容生成最多4,400次，生成失败重试、环境工具路由和框架调用另计，不能把4,400冒充全部API请求数。

建议复杂度为“受控诊断”：运行并发1，单次内容生成失败最多重试1次、全批额外内容生成重试不超过440次；不因质量不满意反复重采文本。到限保留失败和checkpoint，交用户决定。不可恢复的时间/记账错误立即停止；可恢复的服务失败按预登记重试策略处理。

历史 s0 元数据中 random 全run约3小时08分、chronological约2小时42分；环境、服务及代码不同，且个别历史时间字段混用时区，不能据此保证新时长。建议四run累计墙钟运行上限24小时，到限保存并停止；这是待用户批准的资源限制，不是预测。费用由于服务单价与工具调用量尚未核定，不编造金额；实现验收后、正式启动前给出模型、价格来源/计费方式和费用上限，或取得用户明确接受按运行量/时长控制的授权。本轮不做付费试跑。

可选扩展仅登记：timestamp两臂补齐3seeds，累计8run；四格都补齐3seeds，累计12run；再加统一调度与回流规则的chronological三个seed，累计15run。三个选择不自动串行执行。每周重抽行动时刻、同周Agent传播、停止后段真实输入、纯兴趣匹配消融和重新校准都不在首批范围。

必须实际通过的功能验收：

1. 同一条周五帖在timestamp周二不可见、周六可见；preload在同周周二有资格，官方例外时刻在两条件一致。
2. 本周Agent帖即使早生成，也不进入后续小时feed；次周释放且帖龄正确。
3. 同批换Agent遍历顺序，确定性feed、D/R/U一致；LLM异步完成顺序不改变稳定键及同批快照。构造候选内容、状态与行动时刻完全相同的样例，两种到达模式应给同一Agent/周相同feed；打乱外部帖入池顺序或运行期post_id也不得改变结果。
4. 行动机会、曝光、成功发布、失败状态和周统计守恒；空池、短feed和末批之后到达均有正确记录。
5. 断点恢复不重复注入、发帖或曝光；确定性状态和冻结响应回放与不中断执行一致。远端LLM重新采样不要求正文逐字一致。
6. 旧配置用离线特征样例核对行为未被新模式意外改变；不重新运行旧9run。
7. 四格配置除algorithm和arrival_mode及必要run路径外，共同设定逐值一致；在每个algorithm内两到达条件只差arrival_mode和路径。
8. 日志保存实际上下文、候选池计数、发布时间、可用时间、行动时间及来源；不只保存最后一批状态冒充全周状态。
