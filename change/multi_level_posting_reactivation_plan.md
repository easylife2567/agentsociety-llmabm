# 多级发帖与二次回流机制计划书

> 状态：机制设计提案，尚未修改代码、尚未运行仿真
> 目的：在保留现有推荐时序和类型公平约束的前提下，使内容供给机制能够表达强弱不同的发言动机，并解释真实数据中 W19 之后的二次升温。

## 一、结论摘要

建议采用“**净冲击衰减 + 集体注意力再激活 + 条件发帖强度**”的组合机制：

1. 把活跃人口拆成常态盘、第一波事件冲击和第二波回流，避免把常态参与者重复计算进衰减过程。
2. 悼念、教育、其他和玩梗四类 Agent 使用相同的多级发帖门槛，每周可发 0～3 帖；营销 Agent 仍只允许发 0 或 1 帖。
3. 所有 Agent 读取同一个“集体注意力再激活信号”，不设置类型专属门槛或类型专属加成；不同类型的聚合反应由 Agent 原有身份、兴趣和所见信息流自然产生。
4. 第二波信号采用近期新增曝光、内容或互动的流量指标，并随时间衰减，不直接使用永久累积量，以免尾部持续过冲。
5. 保留现有“本周发帖暂存、下一周进入推荐”的传播时序，不另加延迟模块。

本方案来自真实数据和此前数值计算的机制诊断，**不是仿真结果，也不能被表述为已经验证的因果结论**。

## 二、当前方案及其局限

### 2.1 当前机制

当前 Agent 的发言决策以沉默螺旋与注意力衰减共同决定：

\[
U_{it}=D_{it}R_{it}, \qquad U_{it}\ge activity_i \Rightarrow \text{发帖}
\]

其中：

- \(D_{it}\) 表示 Agent 从本人信息流中感知到的意见气候；
- \(R_{it}\) 表示重复曝光造成的注意力衰减；
- \(activity_i\) 是 Agent 的个体发言门槛；
- 每个 Agent 每周只能选择“不发”或“发 1 帖”。

Agent 在本周产生的帖子先进入 `_pending_agent_posts`，本周收尾时由 `_flush_pending_to_pool()` 并入内容池，随后 `_open_tick()` 才装配下一周信息流。因此，本周帖子不会刺激本周自己的发言决策，只会从下一周开始传播。

### 2.2 当前方案解释不了的现象

当前方案近似把去世后的讨论理解为“一次冲击后持续降温”，并将玩梗扩散与其他内容的衰减视为相对独立的过程。这会产生三个问题：

1. 达到门槛一点点和远超门槛的 Agent 都只发 1 帖，无法表达现实中的发言强度差异。
2. 如果从包含常态参与者的总量曲线估计衰减速度，随后又额外叠加常态盘，就会重复计算常态供给。
3. 纯衰减无法解释 W19 之后悼念、营销和玩梗等内容同时回升的尾部结构。

## 三、新机制设计

### 3.1 第一层：活跃人口分解

对每种内容类型 \(T\)，将活跃人口写为：

\[
A_{T,t}=B_T+X^{death}_{T,t}+X^{react}_{T,t}
\]

其中：

- \(B_T\)：类型 \(T\) 的常态参与底盘；
- \(X^{death}_{T,t}\)：由去世事件触发的第一波净冲击；
- \(X^{react}_{T,t}\)：事件重新进入公众视野后产生的回流人口。

第一波净冲击按类型衰减：

\[
X^{death}_{T,t}=X^{death}_{T,t-1}\exp(-\lambda_T)
\]

这里的 \(\lambda_T\) 管理的是“临时进入者退出的速度”，所以必须使用**活跃作者数的净冲击**估计，不能从帖子总量直接估计。

### 3.2 第二层：集体注意力再激活

引入所有 Agent 共同读取的再激活信号 \(H_t\)：

\[
H_t=\rho_HH_{t-1}+g(\Delta C^{meme}_t,M^{new}_t,I^{meme}_t)
\]

其中：

- \(\Delta C^{meme}_t\) 是本周新增玩梗曝光，而不是历史累计曝光总量；
- \(M^{new}_t\) 是本周新增玩梗内容或新增采用者；
- \(I^{meme}_t\) 是本周玩梗内容互动；
- \(0\le\rho_H<1\) 控制再激活信号自然消退。

该信号表示“这个事件重新变热了”，玩梗可以是重要来源，但不预设为唯一来源。若后续证据表明存在新的官方消息或跨平台传播，可将其作为 \(g(\cdot)\) 的共同外部输入，而不改变门槛结构。

为避免重新引入已经退役的类型差异增益 G，本方案规定：

- 所有类型读取相同的 \(H_t\)；
- 不为任何内容类型设置专属再激活门槛；
- 不把真实 W20～W22 结果直接写进 \(H_t\)；
- 类型间的不同回流幅度由 Agent 的既有人设、兴趣匹配、意见气候和信息流构成产生。

### 3.3 第三层：条件发帖强度

在原有效用上加入共同再激活信号，形成标准化发言强度：

\[
U'_{it}=D_{it}R_{it}F(H_{t-1}), \qquad
z_{it}=\frac{U'_{it}}{activity_i}
\]

其中 \(F(H)\) 对所有类型使用同一形式和同一参数。采用 \(H_{t-1}\) 是为了保持“本周内容最早影响下一周”的现有时序。

对悼念、教育、其他和玩梗四类 Agent，使用统一门槛：

\[
N_{it}=
\begin{cases}
0,&z_{it}<1\\
1,&1\le z_{it}<\kappa_2\\
2,&\kappa_2\le z_{it}<\kappa_3\\
3,&z_{it}\ge\kappa_3
\end{cases}
\]

约束为：

- 四类 Agent 共用 \(1,\kappa_2,\kappa_3\)，不允许按类型单独调门槛；
- 单个 Agent 每周最多 3 帖；
- 达到一级门槛只是恢复当前的“发 1 帖”，只有明显更强的动机才会进入二级或三级。

营销 Agent 不采用多级机制：

\[
N^{marketing}_{it}=\mathbf{1}(z_{it}\ge1)
\]

即营销 Agent 仍能对事件再度升温作出反应，但每周最多发 1 帖。这符合营销内容通常借势一次、而非围绕同一事件连续表达多次的行为逻辑。

### 3.4 第四层：从人口到帖子供给

模型必须区分以下三个量：

1. **活跃作者数**：本周至少发过一次帖的人数；
2. **条件发帖强度**：一个活跃作者本周发了几帖；
3. **帖子供给量**：所有活跃作者帖子数之和。

聚合关系为：

\[
P_{T,t}=\sum_{i:type(i)=T}N_{it}
\]

不能用作者数直接代替帖子量，也不能用帖子量的衰减率直接控制作者退出。

## 四、对 DeepSeek 三点意见的裁定

### 4.1 关于“半衰期取错口径”：接受原则，不直接接受参数

DeepSeek 指出：如果半衰期从包含常态盘的总量曲线估计，之后又叠加常态盘，会造成超调。这个结构性判断成立。

它给出的候选诊断值为：

| 类型 | 总量口径半衰期 | 扣除其所取常态盘后的半衰期 |
|---|---:|---:|
| 悼念 | 0.90 | 0.74 |
| 其他 | 1.56 | 1.11 |
| 营销 | 2.50 | 1.32 |
| 教育 | 4.09 | 2.64 |

这些数值可以保留为敏感性分析候选，但不能直接成为最终参数，原因如下：

- DeepSeek 使用的 W15 悼念“651”和 W21 悼念“410”是活跃作者数；对应帖子数分别是 736 和 449，二者不能混用。
- W17～W19 不一定是稳定常态盘：W17 可能仍有第一波残留，W19 已接近二次升温。
- 悼念早期呈现“先断崖、后缓降”，单一指数的拟合误差也会造成超调，不能把全部误差归因于常态盘重复计算。

最终参数估计采用以下顺序：

1. 优先用事件前安静窗口估计 \(B_T\)，并与 W17～W18 的安静期候选值做敏感性比较；不机械使用 W17～W19 均值。
2. 使用 W13～W18 的活跃作者净冲击拟合 \(\lambda_T\)，将 W19 以后作为二次升温阶段排除在第一波衰减拟合之外。
3. 同时比较“先估 \(B_T\) 再拟合净冲击”和“联合估计 \(B_T, X^{death}_{T,0},\lambda_T\)”两种结果。
4. 单独计算每类每周的条件发帖强度 \(P_{T,t}/A_{T,t}\)，再由人口和强度共同预测帖子供给。

### 4.2 关于“尾部回流没人管”：接受，列为最重要修正

真实活跃作者数据明确显示 W19 以后发生了阶段变化：

| 类型 | W19 | W20 | W21 | W22 |
|---|---:|---:|---:|---:|
| 悼念 | 125 | 169 | 410 | 340 |
| 营销 | 497 | 598 | 550 | 683 |
| 玩梗 | 118 | 726 | 2133 | 3004 |

纯衰减模型把悼念 W21 预测到约 7 人，而真实值为 410 人，说明这不是普通随机误差，而是模型遗漏了再激活阶段。因此，第一波衰减与玩梗扩散不能继续作为互不作用的独立模块。

但这些残差只能证明“需要二次再激活机制”，尚不能单凭时间顺序证明“玩梗单向导致所有类型回流”。本方案采用共同注意力信号 \(H_t\)，保留对玩梗驱动、外部消息和平台再曝光等来源的可检验空间。

### 4.3 关于“下一周才参与推荐已经实现”：完全接受

现有环境在 `custom/envs/curation_dynamics_space.py` 中已经按以下顺序运行：

1. 第 1198 行调用 `_flush_pending_to_pool()`，将本周暂存帖子并入内容池；
2. 第 1224 行调用 `_open_tick(next_week)`，装配下一周信息流。

因此，不需要实现新的延迟机制，也不会额外引入一周相位偏移。该条应从“待开发功能”改为“实现时必须保持的不变量”：未来放开四类 Agent 的多帖限制时，同一 Agent 的多条帖子仍必须全部写入 pending 队列，不能逐帖即时刷新本周 feed 或重新计算本周效用。

## 五、与当前方案的核心区别

| 方面 | 当前方案 | 新方案 |
|---|---|---|
| 发帖决策 | 每周 0 或 1 帖 | 四类 Agent 每周 0～3 帖；营销仍为 0 或 1 帖 |
| 强动机表达 | 超过门槛后不再增加供给 | 动机越强可进入更高发帖档位 |
| 人口衰减 | 容易把总量直接解释为一次衰减 | 常态盘、第一波净冲击、第二波回流分开 |
| 后期走势 | 第一波后原则上持续下降 | 共同注意力信号允许事件再次升温 |
| 类型关系 | 衰减与玩梗扩散相对独立 | 所有类型通过共同信号发生联动 |
| 类型公平 | 单一门槛 | 四类共用多级门槛；无类型专属再激活加成 |
| 推荐时序 | 本周暂存、下一周传播 | 完全保留 |

## 六、后续实施与验证计划

### 6.1 参数标定

- 从真实打标数据分别构造“周 × 类型”的活跃作者数和帖子数。
- 估计常态盘及其不确定区间，再拟合第一波净冲击半衰期。
- 用 W19～W22 的新增曝光、内容和互动构造多个 \(H_t\) 候选，不直接使用真实类型总量作为决策输入。
- 先通过数值计算检查量级、相位和尾部稳定性，再决定是否进入仿真实现。

### 6.2 未来消融比较

至少比较以下机制版本：

1. 当前方案：单帖 + 纯衰减，无再激活；
2. 仅多级发帖：多帖 + 纯衰减；
3. 仅二次回流：单帖 + 再激活；
4. 完整方案：多级发帖 + 再激活。

该比较用于区分“供给强度不足”和“人口回流缺失”分别解释了多少误差，避免一次加入多个机制后无法归因。

### 6.3 验收标准

- 活跃作者数、条件发帖强度和帖子供给量在数据、计算与报告中始终使用不同字段和单位。
- 常态盘只计算一次；\(\lambda_T\) 只控制第一波净冲击，不直接控制帖子总量。
- 悼念、教育、其他、玩梗使用同一组多级门槛，营销每周发帖数始终不超过 1。
- 再激活信号采用流量或近期加权存量，具有明确衰减，不因历史累计值单调增长而永久维持高位。
- W19～W22 可以出现跨类型回流，但模型不直接读取真实 W19～W22 目标值生成该回流。
- W\(t\) 产生的帖子最早只影响 W\(t+1\)，同周内不刷新 feed、不形成自我刺激。
- 生成性验证关注阶段顺序、转折时间和数量级；只有正式仿真完成后，才能将结果称为仿真证据。

## 七、风险与边界

- **过度拟合风险**：常态盘、半衰期、再激活强度和多帖门槛不能同时按同一条真实曲线自由调节；应采用分层标定与消融验证。
- **供给膨胀风险**：多级机制上限固定为 3，并监测人均发帖量和总供给量；若整体过冲，优先检查强度尺度，而不是设置类型专属门槛。
- **永久回流风险**：不得直接把累计曝光 \(C_t\) 当作 \(H_t\)，必须使用增量、滑动窗口或指数衰减存量。
- **因果过度解释风险**：真实尾部曲线支持“二次升温存在”，不单独识别其来源；玩梗的因果作用仍需通过后续反事实或消融比较检验。
- **研究主线边界**：共同再激活信号属于 Agent 所处的信息环境，不等于在推荐排序中重新加入帖子级热度项；三种推荐算法的排序机制仍应保持可比较。

## 八、最终决策

1. 接受多级发帖机制，但仅适用于悼念、教育、其他和玩梗四类 Agent；营销 Agent 保持单帖机制。
2. 接受“净冲击口径”原则，拒绝未经重新估计就直接采用 DeepSeek 给出的具体半衰期。
3. 正式加入共同注意力再激活项，替代“第一波衰减与第二波扩散完全独立”的假设。
4. 保留现有跨周传播结构，不重复开发延迟功能。
5. 在实现前先完成分层数值标定和四版本消融设计；本文件本身不构成仿真验证。
